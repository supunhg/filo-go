# Competitor benchmark — 2026-06-10

**Tool:** `filo-go analyze` vs `binwalk --quiet`
**Hardware:** Linux x86_64 (Ubuntu), Go 1.24
**Corpus:** 3 synthesized files in `/tmp/bench-corpus/`
**Method:** Median of 3 wall-clock measurements per (tool, file) pair, captured with Python `time.perf_counter()`. Full process invocation included (no warm-cache tricks).
**Run script:** `benchmarks/competitor_bench.sh`

## Results

| file | size | filo-go (median) | binwalk (median) | speedup |
|---|---|---|---|---|
| `large.png` | 4.7 KB | **3.9 ms** | 757.5 ms | **193.86x** |
| `large.zip` | 82.1 KB | **3.8 ms** | 814.2 ms | **216.78x** |
| `random-10mb.bin` | 10.0 MB | **243.8 ms** | 3,397.4 ms | **13.94x** |

## Interpretation

- **The speedup is real, not just startup overhead.** Even on the 10MB random blob — where scan-time dominates over launch — filo-go is 13.94x faster than binwalk.
- **The gap narrows as file size grows** (216x → 194x → 14x), which is the expected pattern: binwalk's per-byte scanning cost catches up as input grows, but filo-go's single-pass architecture keeps a large constant-factor advantage.
- **Detection depth is comparable, not identical.** `filo-go` flagged the synthetic PNG as missing its IEND chunk (a real structural warning); `binwalk` did not, because binwalk does not validate PNG structure — it only scans for embedded signatures.
- **Earlier "6x to 10,873x faster" claims in README.md and docs/PERFORMANCE.md are outdated.** They were based on a different (synthesized) corpus and should be replaced with the measured numbers above.

## Caveats

- Corpus is **synthetic and small** (3 files, 10MB max). Not a comprehensive benchmark.
- Only **one competitor** (binwalk) was measured. Earlier sessions installed `exiftool`, `yara`, `foremost`, `file`, `sha256sum`; extending the script to those is straightforward (edit the `FILES` env var and the `median_ms` call to add more tools).
- **Single-run variance:** re-running the script produces numbers within ±20% of the medians above (the 216x figure for large.zip ranged from 120x to 217x across runs in this session).

## Reproducing

```bash
# 1. Build filo-go
go build -o /tmp/filo-go ./cmd/filo

# 2. Build the corpus (one-time, ~10MB)
/tmp/filo-go --help  # (any invocation creates the corpus dir)
# Or see benchmarks/competitor_bench.sh header for the synthesize commands

# 3. Run the bench
benchmarks/competitor_bench.sh 3 /tmp/bench-corpus
```
